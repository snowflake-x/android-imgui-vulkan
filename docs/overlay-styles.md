# 性能悬浮显示样式

在「插件列表 → 性能检测 → 显示样式 → 悬浮显示风格」选择：

- **MetalHUD**：原有的当前值、最小值、最大值与蓝色帧时间曲线；旧配置默认保持此样式。
- **微星小飞机 / RTSS**：参考 Afterburner/RTSS OSD 的紧凑等宽文字布局。GPU 与帧数据为橙色，CPU 为绿色，内存为青色，图形 API 为紫色，FPS 使用较大字号。不是 MSI 官方集成。

两种样式均由 C++ + ImGui 绘制，共用采样结果、字体、透明度、位置及刷新间隔。选择会保存到原生配置，运行中切换会更新普通悬浮窗和 Root 图层。配置格式升级至 v8，继续读取 v1–v7。

RTSS 的 CPU/GPU 负载、频率及系统 RAM 行随对应采集字段开关显示；其他传感器可通过「附加传感器行」显示。FPS / Pre 关闭时显示 OFF，缺失数据为 -- 或 N/A，不填充推测值。橙色曲线仍表示呈现帧时间。GPU time 保留 ms/batch 或 ms/window，GPU mem 是共享系统内存用量，APP 是主进程 RSS。完整解释仍在 App 内的数据说明页。

## 触摸穿透

普通悬浮窗不接收触摸或焦点，Android 12+ 从 InputManager 读取设备的最大遮挡透明度并保留舍入余量。此上限独立于用户设置的 HUD 背景不透明度。

Root 显示进程仅为自身 SurfaceControl 图层设置 trusted overlay 标记，避免系统将它计入不可信触摸遮挡；不创建输入通道，不修改全局触摸安全策略。固件不支持该接口或拒绝操作时沿用 Root 显示错误报告流程。

设备验证应分别启用普通悬浮窗和 Root 图层，在 HUD 覆盖区域点击、长按、拖动游戏控件，并覆盖横竖屏切换、样式切换及收起/展开。自动化测试验证了透明度边界和 Android 15/16 的接口存在性，不能代替固件上的真实触摸验证。
