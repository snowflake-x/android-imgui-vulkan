# 刷新调度与前台切换

性能插件设置提供 250 / 500 / 1000 / 2000 / 5000 ms 刷新间隔，旧配置保持原值。该间隔控制原生结果发布和各采集通道的调度；HUD 与实时通知消费同一个发布序号，App 页面和停止监测后的设备信息轮询也采用该设置。显示动画、Surface 几何检查与服务权限看门狗不属于数据采样，可以更频繁执行。

固定八个工作线程分别负责前台、呈现帧、图形 API、进程和 GPU 内存、GPU 耗时、引擎、硬件文件及 Android 系统 API。每个通道独占 Collector、命令和统计历史，最多一个任务，不积压任务。发布线程只合并已完成结果，不等待慢通道，也不通过创建无限线程加速。所有线程先统一取消再 join；探针清理失败状态仍跨会话保留。

前台查询优先独立调度，正常情况下在下一发布周期显示识别结果；新应用指标独立预热。切换包名或 Android 用户后取消旧应用任务，清空其指标和帧历史，后续迟到结果按代次丢弃。Root、采样字段、周期及传感器配置变化也使旧任务失效。全局硬件信息无需因 App 切换而重置。

采集完成时间不能由 App 保证：例如 GPU work-period 跟踪要等待 1.1 秒观察窗口，系统 dumpsys、Root 调度和通知限流也可能超过所设间隔。因此短周期不会凭空生成新测量。忙通道跳过新任务，保留同一目标的结果并记录从任务开始计算的年龄，超过两周期显示 Delayed，超过 15 秒清除。诊断提供 `refresh_interval_ms`、`sample_age_ms_*`、`sample_duration_ms_*` 和 `sampling_delays`。帧历史仅添加新采样，重复发布不重复累计帧。应用切换时无条件清空旧目标结果，不使用上述保留窗口。

前台查询命令有独立预算（至少 500ms）；没有及时识别目标时明确显示不可用，禁止继续归属到旧 App。取消遵循既有 tracefs 清理协议，慢清理不会阻塞其他通道。普通悬浮窗权限撤销立即停止，不必等到数据刷新周期。

验证：并发测试模拟慢 API 任务，检查帧通道独立推进、单通道无重叠/积压、切换应用迟到结果丢弃、设置变化失效与统一取消。保留原有 Surface、GPU 采集、权限与生命周期回归测试。具体真机延迟需在一加固件上观察诊断中的各通道耗时。
